# Langues : français (défaut) et arabe (RTL)

Code : `src/i18n/` (contexte, `messages.js`, `content.js`), `src/components/LanguageSwitcher.jsx`, `src/styles/rtl.css`.

## Fonctionnement

- Français par défaut ; bouton « العربية / Français » dans l'en-tête, et les deux langues dans le menu mobile.
- Choix mémorisé dans le navigateur (`localStorage`, clé `mpc.lang`), y compris pour les visites suivantes.
- `<html lang="ar" dir="rtl">` en arabe ; remis en français/LTR en entrant dans l'administration (qui reste en français).
- Police arabe (Noto Kufi Arabic pour les titres, Noto Sans Arabic pour le texte) chargée uniquement en arabe.
  Les mots latins (marques, produits) gardent les polices de la marque.
- Prix : chiffres latins (usage marocain) + « درهم ». Villes du formulaire affichées en arabe, valeur envoyée inchangée.
- Arabe standard moderne ; la cliente est tutoyée au féminin (comme « Restez informée » du thème).
  [À VALIDER] Ce choix de ton peut être rendu neutre si la cible n'est pas exclusivement féminine.

## Ce qui est traduit

| Source | Arabe |
|--------|-------|
| Textes de l'interface (boutons, formulaires, erreurs, notifications, panier, commande, confirmation, 404, accessibilité) | ✅ tous (`messages.js`) |
| Textes d'origine du thème (accueil, annonce, menu, avantages), valeurs par défaut des sections, catégories, ingrédients | ✅ si le texte est **resté celui d'origine** (`content.js`) |
| Texte du thème modifié dans l'admin | ❌ affiché tel quel (pas de traduction inventée) |
| Contenu produit (description, ingrédients, conseils, type de peau, phrase courte) | ❌ en français : base de données sans champ arabe ; affiché avec `dir="auto"` pour rester lisible |
| Messages d'erreur détaillés du serveur | remplacés par un message arabe générique (le serveur répond en français) |

Pages inexistantes dans la boutique (non créées) : connexion / inscription client, espace client, pages
informatives (CGV, confidentialité…).

## Pour traduire aussi les produits et le thème modifié

Nécessite des champs arabes en base et dans l'administration (ex. `name_ar`, `summary_ar`… ou un champ
`translations` JSON), puis un choix de langue dans l'API publique. Changement du schéma MySQL → à décider.

## Ajouter un texte d'interface

Ajouter la clé dans `fr` **et** `ar` de `src/i18n/messages.js`, puis `const { t } = useI18n(); t('ma.cle')`.
Une clé absente en arabe affiche le français (et un avertissement en développement).
