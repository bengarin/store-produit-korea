# Langues : français (défaut) et arabe (RTL)

Code : `src/i18n/` (contexte, `messages.js`, `content.js`), `src/components/LanguageSwitcher.jsx`, `src/styles/rtl.css`.

## Fonctionnement

- Français par défaut ; bouton « العربية / Français » dans l'en-tête, et les deux langues dans le menu mobile.
- Choix mémorisé dans le navigateur (`localStorage`, clé `mpc.lang`), y compris pour les visites suivantes.
- `<html lang="ar" dir="rtl">` en arabe ; remis en français/LTR en entrant dans l'administration (qui reste en français).
- Police arabe (Noto Kufi Arabic pour les titres, Noto Sans Arabic pour le texte) chargée uniquement en arabe.
  Les mots latins (marques, produits) gardent les polices de la marque.
- Prix : chiffres latins (usage marocain) + « درهم ». Villes du formulaire affichées en arabe, valeur envoyée inchangée.
- Arabe standard moderne, **ton neutre** : pluriel de politesse (اكتشفوا، طلبكم) ou tournures impersonnelles
  (يُرجى إدخال…), adapté à tous les clients.

## Ce qui est traduit

| Source | Arabe |
|--------|-------|
| Textes de l'interface (boutons, formulaires, erreurs, notifications, panier, commande, confirmation, 404, accessibilité) | ✅ tous (`messages.js`) |
| Textes d'origine du thème (accueil, annonce, menu, avantages), valeurs par défaut des sections, catégories, ingrédients | ✅ si le texte est **resté celui d'origine** (`content.js`) |
| Texte du thème modifié dans l'admin | ❌ affiché tel quel (pas de traduction inventée) |
| Contenu produit (nom affiché, phrase courte, description, description longue, ingrédients, bienfaits, conseils, types de peau, pictos) | ✅ si saisi dans l'admin (bloc « Version arabe » de la fiche produit) ; sinon le français s'affiche (`dir="auto"`) |
| Nom des catégories | ✅ si saisi (même bloc ; enregistré sur la catégorie, commun à tous ses produits) |
| Messages d'erreur détaillés du serveur | remplacés par un message arabe générique (le serveur répond en français) |

Pages inexistantes dans la boutique (non créées) : connexion / inscription client, espace client, pages
informatives autres que la politique de confidentialité (CGV, mentions légales…).

## Contenus produits en arabe (base et administration)

- Colonnes **ajoutées** (migration `catalog 0004`, aucune suppression ni modification des données existantes) :
  `display_name_ar`, `short_description_ar`, `summary_ar`, `description_html_ar` (HTML assaini comme le français),
  `ingredients_ar`, `benefits_ar`, `usage_steps_ar`, `skin_types_ar`, `ProductHighlight.label_ar`, `Category.name_ar`.
- Admin : bloc « Version arabe » de la fiche produit, saisie de droite à gauche, texte français affiché en repère.
  Mêmes droits que les produits (Propriétaire, Admin, Éditeur de contenu ; Gestionnaire et Analyste en lecture).
- API publique : `translations.ar` présent uniquement s'il existe des textes arabes ; la boutique choisit selon la langue.
- Non traduisibles pour l'instant : noms d'options/valeurs de variantes (ex. « Contenance », « 50 ml »), textes
  alternatifs des images, contenu SEO serveur (titre/description servis aux robots : français).

## Thème modifié dans l'admin

Un texte du thème modifié par l'équipe reste affiché tel quel en arabe (pas encore de champ arabe dans l'éditeur de thème).

## Ajouter un texte d'interface

Ajouter la clé dans `fr` **et** `ar` de `src/i18n/messages.js`, puis `const { t } = useI18n(); t('ma.cle')`.
Une clé absente en arabe affiche le français (et un avertissement en développement).
